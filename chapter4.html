LEARNING FRAMEWORKObjectives, sequence, and key distinction
LEARNING OBJECTIVE

What must happen inside every router before a packet can leave on the correct link?

CONCEPT SEQUENCE

Parse input → longest-prefix or match-action lookup → cross the switching fabric → queue and schedule → transmit a new link frame.

KEY DISTINCTION

Forwarding is a local data-plane action. Routing is the control-plane process that creates forwarding state.

4.1 The data plane moves one datagram at a time

The network layer transfers transport segments between hosts. At the sender it wraps a segment in an IP datagram; routers forward that datagram across links; at the destination it delivers the segment upward. IP offers best-effort service: no guarantee of delivery, order, bandwidth, or maximum delay.

DATA PLANELocal and fast

Uses installed rules to select an output for each arriving packet. It operates at line rate inside every router.

CONTROL PLANENetwork-wide and slower

Computes routes and installs forwarding state using distributed protocols or a logically centralized controller.

FORWARDING ≠ ROUTING

Forwarding is the per-packet action at one router. Routing determines end-to-end paths and creates the tables that forwarding uses.

Input processing and switching must keep pace with aggregate arrival traffic. A memory fabric is simple but may copy each packet twice. A shared bus avoids copies but becomes a shared bottleneck. An interconnection network such as a crossbar allows several nonconflicting transfers at once.

4.3 Queues form wherever arrival temporarily exceeds service

An input queue can suffer head-of-line blocking: its first packet waits for a busy output while packets behind it could have used free outputs. Output queues form when several inputs send to one output faster than its link can transmit.

BUFFERING TRADEOFF

Too little buffering drops bursts. Too much can keep stale packets waiting for a long time, producing bufferbloat. Active queue management can mark or drop packets before a buffer is completely full.

4.4 IPv4 combines a forwarding header with hierarchical addressing

An IPv4 address is a 32-bit identifier assigned to an interface. CIDR writes an address block as a prefix plus length, such as 203.0.113.0/24. Aggregation lets one route represent many smaller networks.

SUBNETTING

Splitting 192.168.10.0/24 into four equal blocks borrows two host bits, producing /26 networks at .0, .64, .128, and .192. Each block contains 64 total addresses; under traditional subnet rules, 62 are assignable to hosts because the network and directed-broadcast addresses are reserved.

4.5 NAT changes endpoints; IPv6 changes the address space

NAT

Translate address and port

An edge gateway maps private source address/port pairs to a public address and unique ports. Reply traffic reverses that stateful mapping.

NAT conserves IPv4 addresses, but complicates inbound connections, mobility, and protocols that carry addresses in payloads.

IPv6

128-bit addressing

A fixed 40-byte base header removes the header checksum and router fragmentation. Extension headers carry optional functions.

IPv6 uses multicast and anycast rather than broadcast. Dual stack, tunneling, and translation support gradual migration.

FRAGMENTATION

IPv4 routers may fragment an oversized datagram and the destination reassembles it. IPv6 routers do not fragment transit packets; the source adapts after receiving ICMPv6 Packet Too Big information or through packetization-layer probing.

4.6 Generalized forwarding matches fields and applies actions

Traditional destination forwarding matches an IP prefix and chooses an output. A generalized flow table can match fields from link, network, and transport headers, then forward, drop, copy, modify, count, meter, or send a packet to a controller.

OpenFlow is one interface for programming such rules. Middleboxes use similar packet processing for firewalls, load balancing, NAT, caching, and intrusion detection. Their state and policy can complicate end-to-end reasoning.

4.7 The Internet survives change through narrow interfaces

IP HOURGLASS

One common waist

Many applications run above IP and many link technologies run below it. A small universal network layer allows both sides to evolve independently.

END-TO-END ARGUMENT

Place functions at endpoints

When only endpoints can fully verify correctness, the network should provide a simple service and applications should implement complete reliability or security.

These are design guides rather than absolute rules. Link retransmission can still improve performance, and in-network policy can still protect or optimize shared infrastructure.

Advanced analysis Forwarding, queueing, and address architecture

The data plane is a high-speed packet-processing pipeline. These additions cover the router internals, queue disciplines, complete IP behavior, transition mechanisms, and middleboxes needed to understand real forwarding.

A router separates line-rate forwarding from slower control
INPUT · FABRIC · OUTPUT

An input port terminates the physical/link layers, parses headers, performs a FIB lookup, and may classify or filter the packet. The switching fabric transfers the packet to an output. The output queues, schedules, rewrites the link header, and transmits. A routing processor handles control protocols and management rather than every packet.

Switching fabrics can use memory, a shared bus, or an interconnection network. Memory and bus designs share one transfer resource. Crossbars and multistage fabrics can move several packets in parallel when they target different outputs. Input queues can suffer head-of-line blocking when the first packet waits for a busy output while packets behind it could otherwise move.

Buffer management and scheduling define service under load
FIFO · PRIORITY · RR · WFQ

FIFO transmits in arrival order. Strict priority serves the highest nonempty class and can starve lower classes. Round Robin visits nonempty queues in turn. Weighted Fair Queueing approximates configurable shares based on packet finish times and weights.

Buffer policy decides what to admit and what to drop or mark. Tail drop rejects arrivals only when full. Active queue management signals persistent queueing earlier. Output queueing occurs when the fabric delivers packets faster than the link transmits; input queueing occurs when the fabric or desired output is unavailable.

IPv4 fields support forwarding, fragmentation, and upper-layer delivery
TTL · PROTOCOL · FRAGMENTS

The IPv4 header carries version, header length, service bits, total length, identification, flags, fragment offset, TTL, upper-layer protocol, header checksum, and addresses. Every router decrements TTL and recomputes the header checksum; expiry normally triggers ICMP Time Exceeded.

When fragmentation is allowed, fragments share an identification value and use offsets plus the More Fragments flag. Reassembly occurs at the destination because routers do not retain full datagram state. Fragment loss discards the whole original datagram, which is one reason modern endpoints prefer Path MTU Discovery and avoid fragmentation.

Addressing combines subnets, CIDR, DHCP, and NAT
PREFIXES · LEASES · TRANSLATION

A CIDR prefix divides an address into network and host portions. Routers aggregate prefixes to reduce table size and apply longest-prefix match when an aggregate and a more specific route both match. A subnet groups interfaces that can reach one another without crossing a router.

DHCP leases an address and supplies subnet mask/prefix, default gateway, DNS resolver, and lifetime. NAT maps internal address/port tuples to external tuples and reverses the mapping for returning traffic. It conserves public IPv4 addresses and hides internal numbering, but complicates inbound connections, peer-to-peer reachability, and protocols that embed addresses.

IPv6 simplifies transit processing and changes extension handling
128 BITS · EXTENSION HEADERS

The fixed IPv6 base header removes the IPv4 header checksum and router fragmentation, renames TTL as Hop Limit, and uses Next Header to identify an extension or transport protocol. A Flow Label can identify related traffic. Sources use ICMPv6 Packet Too Big information and may fragment with a fragment extension header.

Transition techniques include dual stack, tunnels that carry IPv6 inside IPv4, and translation when only one side supports IPv6. Neighbor Discovery replaces ARP and also supports router discovery and address configuration. IPv6 provides address space and cleaner forwarding; it does not automatically provide encryption or eliminate routing policy.

Generalized forwarding and middleboxes extend match–action
MATCH · ACTION · STATE

A programmable forwarding table can match ingress port, link fields, IP prefixes, protocol, and transport ports, then forward, drop, mirror, modify, meter, count, or send a packet to a controller. Priorities resolve overlapping rules; counters provide traffic evidence.

Middleboxes include NATs, firewalls, load balancers, proxies, WAN optimizers, and intrusion-prevention devices. Some are stateless; others track connections or application messages. They add useful policy and protection but can violate end-to-end assumptions, create asymmetric-path problems, and slow protocol evolution when they depend on fixed header formats.

Technical reference Data-plane mechanisms

The data plane performs local per-packet forwarding. The control plane decides the forwarding state that makes those local choices form end-to-end paths.

NETWORK SERVICE

Best-effort datagrams

IP does not guarantee delivery, order, timing, or bandwidth. Routers forward each datagram using header fields and a forwarding table. This narrow best-effort service keeps the network core general while endpoints add reliability and application semantics when needed.

ROUTER PIPELINE

Input, switch, output

  1. Input port terminates the link and parses the header.
  2. Lookup selects an output port using the forwarding table.
  3. Switching fabric transfers the packet across the router.
  4. Output port queues, schedules, and transmits it.

Head-of-line blocking occurs when the front packet in an input queue waits even though packets behind it could use free outputs.

QUEUEING

Buffer and schedule contention

Drop-tail discards arrivals when the buffer is full. Active queue management can mark or drop earlier. FIFO serves arrival order; priority serves important classes first; round robin rotates queues; weighted fair queueing approximates configured shares. Larger buffers absorb bursts but can create excessive latency.

IPV4 HEADER

Fields used in transit

Version and header length locate fields; total length sizes the datagram; identification/flags/offset support fragmentation; TTL prevents loops; protocol selects TCP, UDP, or another payload; checksum protects the IPv4 header; source and destination carry 32-bit addresses. Routers decrement TTL and update the checksum.

ADDRESSING

Prefixes, subnets, DHCP, and NAT

CIDR writes an address block as a.b.c.d/x; the first x bits are the prefix. A router uses longest-prefix matching. A subnet groups interfaces that can reach one another without passing through a router. DHCP supplies an address, mask/prefix, default router, DNS resolver, and lease time through discover, offer, request, and acknowledgment.

NAT maps private internal addresses and ports to a public address and chosen ports. It conserves public IPv4 addresses and hides internal addressing, but changes end-to-end reachability and requires state. Port forwarding or traversal mechanisms are needed for inbound peer connections.

IPV6

Larger addresses and simpler transit header

IPv6 uses 128-bit addresses, removes the IPv4 header checksum, and moves optional information into extension headers. Routers do not fragment ordinary transit traffic; endpoints use path MTU discovery. Dual stack, tunneling, and translation support coexistence with IPv4.

GENERALIZED FORWARDING

Match plus action

A programmable switch may match multiple header fields and then forward, drop, copy, modify, meter, or send traffic to a controller. OpenFlow expresses rules with match fields, priorities, counters, actions, and timeouts. This generalizes destination-prefix forwarding.

MIDDLEBOXES AND ARCHITECTURE

Functions beyond ordinary routing

Firewalls, NATs, load balancers, proxies, and intrusion systems inspect or transform traffic. They deliver useful policy and scaling, but can complicate transparency and protocol evolution. The Internet’s common IP layer interconnects diverse links and supports diverse applications—the narrow waist of the architecture.

SWITCHING FABRICS

Move packets across a router

Memory-based switching copies packets through shared memory and is limited by memory bandwidth. A shared bus lets one packet cross at a time and is limited by bus rate. An interconnection network such as a crossbar can transfer several packets in parallel when they use different input/output paths. Internal speedup determines whether the fabric keeps pace with aggregate ports.

INPUT AND OUTPUT QUEUES

Where contention appears

Input queues form when the fabric cannot accept all arrivals or several inputs target one output. Output queues form when many fabric transfers target a link faster than it transmits. Head-of-line blocking can idle an otherwise usable output. Buffer sizing depends on RTT, link capacity, number of flows, burstiness, and desired latency; no single “always large” buffer rule is correct.

SCHEDULING DETAILS

Choose the next packet

FIFO is simple. Strict priority minimizes delay for high classes but may starve others. Round robin skips empty queues and rotates service. Weighted round robin gives configured service quanta. Weighted fair queueing approximates fluid fair sharing using packet finish times. Classification and policing determine which queue receives each packet.

IPV4 ADDRESSING WORKFLOW

Choose next hop and route

  1. Apply the interface prefix mask to decide whether the destination is on-link.
  2. If on-link, use the destination itself as next hop; otherwise use the default router.
  3. Resolve next-hop IP to a link-layer address.
  4. A router compares the destination against forwarding prefixes and selects the longest match.
  5. The router decrements TTL, updates header checksum, and emits a new frame.

Interfaces—not entire routers—hold IP addresses. A multihomed host or router has one address per attached subnet. Address aggregation keeps global tables smaller; a more-specific route can override an aggregate.

FRAGMENTATION AND MTU

Fit datagrams onto links

IPv4 can fragment a datagram using identification, more-fragments flag, and offset; reassembly occurs at the destination. Loss of one fragment prevents reassembly of the original datagram. Path MTU discovery tries to avoid fragmentation by learning the largest usable packet. IPv6 routers do not fragment ordinary transit packets.

DHCP AND NAT STATE

Automatic configuration and translation

DHCP discovery may begin as a broadcast because the client lacks an address and server location. Offer, request, and acknowledgment establish a lease. A NAT table maps an inside address/port and protocol to a public address/port. Return packets reverse the mapping. Timeout and port reuse make NAT state finite; inbound traffic without a mapping is normally rejected unless configured.

IPV6 DETAILS

Address forms and neighbor operation

IPv6 notation compresses hexadecimal zero groups. Link-local addresses support local control; global unicast addresses provide routable identity; multicast replaces many broadcast uses. Neighbor Discovery uses ICMPv6 for address resolution, router discovery, and reachability. Extension headers carry optional functions, while the fixed base header remains simpler for routers.

OPENFLOW EXAMPLE

Match, count, and act

A rule may match ingress port, Ethernet type, VLAN, IP prefix, transport port, or metadata. Priorities resolve overlap. Actions can output to ports, drop, rewrite fields, push/pop tags, or send a copy to the controller. Counters measure packets and bytes. Timeouts remove stale state. The controller must install related rules safely across several switches.

ARCHITECTURAL PRINCIPLES

IP hourglass and end-to-end argument

Many applications run above one common IP layer; many link technologies run below it. Keeping the common waist small promotes interoperability and innovation. The end-to-end argument places correctness functions at endpoints when the network cannot fully guarantee them—for example, only endpoints can ultimately verify that the intended file arrived intact.

FORWARDING VERSUS ROUTING

Forwarding is the local, fast action for one packet. Routing is the network-wide process that computes the state used by forwarding.

4.8 Concept check

Why does longest-prefix matching scale?

Aggregates cover broad regions while longer prefixes add exceptions. Routers need not store one entry per destination host.

Where can queueing occur?

At inputs when switching or a desired output is unavailable, and at outputs when aggregate arrivals exceed the outgoing link rate.

Why does TTL change at each router?

It bounds a datagram’s lifetime so a forwarding loop cannot circulate it forever.

How does match-action differ from ordinary forwarding?

It can match many header fields and apply varied actions, enabling policy and network functions beyond destination-prefix lookup.
